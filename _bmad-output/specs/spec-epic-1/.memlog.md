- (direction) input is INTENT.md (Epic 1: triage data and schema, done-when/must-not-change/out-of-scope), read alongside mcp/triage_server.py (existing consumer of app.db) and seed/tickets.csv, seed/customers.csv (column names) for grounding
- (capability) CAP-1 triage-decision schema: a JSON object with category (billing|bug|access|performance|how-to), priority (P1-P4), route (billing-team|bug-team|access-team|performance-team|how-to-team) and a one-sentence rationale; anything else is rejected with a clear error; success: a well-formed decision validates, a decision with an unknown category/priority/route, a missing field, or extra fields is rejected with a clear error naming the problem
- (capability) CAP-2 seed loader: one command, uv run python load_seed.py, loads seed/tickets.csv and seed/customers.csv into local SQLite file app.db as tables tickets and customers with the same columns as the CSVs; success: after running it, app.db has tables tickets(ticket_id, customer_id, created_at, text) and customers(customer_id, name, plan, open_tickets) matching the CSV rows, and running the command twice leaves app.db in the same state (no duplicates, no error)
- (constraint) Python 3.12 or newer, managed with uv; packages added with uv add
- (constraint) seed/tickets.csv and seed/customers.csv are read-only; load_seed.py only reads them
- (constraint) no network calls and no API keys anywhere in this epic
- (constraint) app.db's tables/columns must exactly match what mcp/triage_server.py already queries (SELECT ticket_id, customer_id, created_at, text FROM tickets; SELECT customer_id, name, plan, open_tickets FROM customers) -- that file is read-only and cannot be adapted to a different schema
- (non-goal) the LangChain triage agent (Epic 2)
- (non-goal) the MCP tools themselves -- mcp/triage_server.py already exists and is not touched this epic
- (non-goal) the eval harness and LLM judge (Epic 3)
- (non-goal) any user interface
