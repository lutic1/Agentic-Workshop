- (direction) input is INTENT.md (rich, pre-sorted into done-when/must-not-change/out-of-scope); express distill, no elicitation; read alongside TRIAGE_POLICY.md, mcp/triage_server.py, seed/*.csv headers and the epic-2 spec for grounding
- (capability) CAP-1 triage decision schema: a decision is a JSON object with category (billing|bug|access|performance|how-to), priority (P1-P4), route (billing-team|bug-team|access-team|performance-team|how-to-team) and a one-sentence rationale; anything else rejected with a clear error; success: valid object accepted, each invalid field value or missing field rejected with an error naming the offending field
- (capability) CAP-2 seed loader: uv run python load_seed.py loads seed/tickets.csv and seed/customers.csv into local SQLite app.db as tables tickets and customers with the same columns as the CSVs; idempotent; success: after one run app.db holds 24 tickets and 20 customers with CSV-matching columns, and a second run leaves identical contents (no duplicates)
- (constraint) Python 3.12 or newer, managed with uv
- (constraint) seed/ files are read-only
- (constraint) no network calls and no API keys anywhere in this epic
- (constraint) mcp/triage_server.py already reads app.db and must keep working unchanged: tickets(ticket_id, customer_id, created_at, text), customers(customer_id, name, plan, open_tickets), app.db at the repo root
- (constraint) app.db is generated and never committed (AGENTS.md)
- (non-goal) the agent, the MCP tools, evals and any user interface are out of scope (Epics 2 and 3)
- (decision) adopt TRIAGE_POLICY.md and mcp/triage_server.py as companions: the policy defines the category/route sets, the server fixes the table and column names
- (assumption) open_tickets loads as an integer, since TRIAGE_POLICY.md's Enterprise rule compares it to 3; other columns load as text
- (question) must route match category per TRIAGE_POLICY.md's one-to-one table (billing->billing-team etc.), rejecting e.g. billing+bug-team? INTENT.md only lists the allowed values
- (question) does 'anything else is rejected' cover extra fields beyond the four, and how strictly is 'one sentence' enforced for rationale (non-empty only, or single-sentence check)?
